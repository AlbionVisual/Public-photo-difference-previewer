# Photo Compare

Статическое приложение для сравнения пар изображений «до/после»: верхняя картинка
обрезается шторкой, нижняя видна целиком. Работает как обычный статический сайт —
без сборки, сервера и зависимостей. Подходит для GitHub Pages.

## Возможности

- Пары изображений листаются списком (или стрелками `P` / `N`).
- Шторка: тянется за верхний ползунок, показывает процент. Линии через изображение
  нет — видно, как пиксели переходят друг в друга.
- Кнопка **«Движение»** (или `A`) прогоняет шторку 15% → 85% → 50%, чтобы было
  видно, что она работает, даже если картинки одинаковые.
- Зум колесом мыши (к курсору) или кнопками `+` / `-`, пан перетаскиванием.
- На телефоне: один палец — панорама, два пальца — зум/панорама.
- Шторка закреплена в координатах экрана: при зуме и панораме граница остаётся
  под ползунком (не «уезжает» вместе с картинкой).
- `0` — сброс вида, `←/→` — шторка (с `Shift` — по 10%), `A` — анимация.

## Структура

```
index.html               # приложение
assets/style.css         # оформление
assets/app.js            # логика (шторка, зум, пан, тач)
pairs.json               # список пар (генерируется)
pairs/<имя>/a.jpg        # «до»
pairs/<имя>/b.jpg        # «после»
pairs/<имя>/meta.json    # необязательно: {"title": "Название пары"}
tools/build_manifest.py  # собирает pairs.json
tools/make_demo.py       # демо-пары (можно удалить)
```

## Пары форматов и зумов

Пары `fmt-*` — центр **Zheltoksan** (место выбрано для демо) в разных форматах.
Название формата **вшито в саму картинку** (слева сверху), поэтому его видно при
любом зуме и панораме:

- z21: PNG ↔ WebP q90 (как в кэше), PNG ↔ WebP lossless, PNG ↔ JPEG q90,
  WebP q90 ↔ WebP q60, WebP q90 ↔ JPEG q90;
- z19: PNG ↔ WebP q90 (общий вид).

Картинки лежат в `formats/z19` и `formats/z21` и переиспользуются парами
(`hideLabels: true` в meta.json отключает угловые подписи, чтобы не дублировать
вшитые).

Исходники форматов лежат в `formats/z19/…` и переиспользуются несколькими парами:
в `meta.json` можно задать пути явно, без копирования файлов:

```json
{
  "title": "z21 · WebP q90 ↔ WebP q60",
  "a": "formats/z21/w90.webp",
  "b": "formats/z21/w60.webp",
  "labelA": "WebP q90",
  "labelB": "WebP q60",
  "zoom": 21
}
```

Если `labelA`/`labelB` не заданы — в углах показываются имена файлов.

## Как добавить пару

1. Создайте папку `pairs/<имя>/` (имя латиницей, без пробелов — это `slug`).
2. Положите туда два изображения **`a.jpg`** и **`b.jpg`** (также можно `.png`,
   `.webp`, `.avif`; главное — одинаковые имена `a.*` и `b.*`).
3. Необязательно: `pairs/<имя>/meta.json`
   ```json
   { "title": "Участок на Ленина, до/после" }
   ```
4. Обновите список:
   ```bash
   python3 tools/build_manifest.py
   ```
5. Закоммитьте и запушьте. Всё.

Рекомендации:

- изображения пары должны быть **одного размера** (иначе второе растягивается и
  приложение предупредит);
- для веба: JPEG/WebP, ширина 2000–4000 px, качество 85–90 — иначе страница
  будет тяжёлой (репозиторий GitHub Pages тоже имеет лимиты);
- имена файлов лучше без пробелов; `slug` — из латиницы, цифр и дефиса.

## Локальный просмотр

`fetch("pairs.json")` не работает через `file://`, нужен любой HTTP-сервер:

```bash
python3 -m http.server 8000
# открыть http://localhost:8000/
```

## GitHub Pages

1. Создайте **новый** репозиторий (например, `photo-compare`).
2. Запушьте этот каталог в ветку `main`.
3. Settings → Pages → Build and deployment → Source: **Deploy from a branch**,
   Branch: `main`, папка `/ (root)` → Save.
4. Через минуту сайт будет на `https://<user>.github.io/photo-compare/`.

Файл `.nojekyll` уже лежит — он отключает обработку Jekyll и не даёт ему
игнорировать файлы, начинающиеся с `_`.

## Управление

| Действие | Мышь / клавиатура | Телефон |
| --- | --- | --- |
| Двигать шторку | тянуть ползунок сверху, `←`/`→` | тянуть ползунок |
| Зум | колесо, `+` / `-` | два пальца |
| Панорама | перетаскивание | один палец |
| Сброс | `0`, кнопка «Сброс», двойной клик | кнопка «Сброс» |
| Показать движение | `A` / кнопка «Движение» | кнопка «Движение» |
| Следующая/предыдущая пара | `N` / `P` | список сверху |

## Как это устроено

Два слоя на весь вьюпорт. В каждом — своя копия изображения с одинаковым
`transform: translate(...) scale(...)`. Верхний слой обрезается
`clip-path: inset(0 X% 0 0)` — в процентах **от вьюпорта**, поэтому граница
остаётся в экранных координатах и не двигается при панораме/зуме. Ползунок тоже
позиционируется в процентах от вьюпорта.
